Upstream compatibility

This file is the single source of truth for the upstream pi baseline that PiKit currently targets. README.md, NOTICE, and the fetch script must not carry a permanent "pinned" version; update this file instead when a new upstream revision is verified.

The baseline is an exact commit, not a floating npm range. Upstream package versions can differ from the nearest release tag because the snapshot may be ahead of the tag; the commit is authoritative for reproduction.

Known deviations

  • Failed assistant messages are not persisted; upstream keeps them and filters them with context_edit { replacement: null }. PiKit applies the exclusion when reading upstream sessions.
  • context_edit non-null replacement is preserved but not interpreted.
  • Compaction does not implement split-turn prefix summaries; cut points back up to the start of the user turn.
  • Deferred responses are recognized but not polled.
  • Full-screen TUI, extensions, skills, themes, MCP, codemode, OAuth login, HTML export, image resizing, branch summarization, telemetry, tool.replay/output_schema are out of phase 1.

Syncing a new upstream revision

  1. Fetch a candidate snapshot:

    PI_UPSTREAM_REF=<commit-or-tag> scripts/fetch-upstream.sh

    Remove .upstream/ first if it already contains a snapshot.

  2. Diff the protocol surfaces:

    • packages/ai/src/types.ts and provider adapters
    • packages/agent/src/agent-loop.ts, agent.ts
    • packages/coding-agent/src/core/session-manager.ts
    • upstream docs/json.md, docs/session-format.md

  3. Add or update tests for changed wire shapes; unknown fields must continue to round-trip through extra.

  4. Run the full gate:

    PIKIT_AGENT_DIR=$(mktemp -d) julia --project=. -e 'using Pkg; Pkg.test()'
julia scripts/check-julia-improvements.jl --phase 1 --strict --upstream .upstream

  5. Update the table above, docs/src/julia-improvements.md, and the PiKit version if behavior or compatibility changed.

  6. Commit, tag, and release PiKit on its own semantic version; do not rewrite historical change records that mention older upstream baselines.

Policy

  • PiKit's version is independent of upstream pi versions.
  • A new upstream revision is "verified" only after the full test gate passes and this matrix is updated.
  • Protocol additions should be additive: unknown fields go to extra, unknown session entries remain UnknownEntry, and new events must not change the meaning of existing ones.
  • README.md links here instead of claiming a permanent pin.
