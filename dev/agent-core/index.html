Agent core

PiAgentCore implements the agent loop on top of PiAISDK: it streams assistant responses, executes tool calls, and turns provider activity into a uniform event stream. It sits between PiAISDK (messages, providers, streams) and PiCodingAgent (tools, sessions, compaction).

Two entry levels are available:

  • run_agent_loop, run_agent_loop_continue and run_loop drive an AgentContext with an AgentLoopConfig, an abort signal and an event callback.
  • Agent is a stateful wrapper that owns messages, tools, listeners and steering/follow-up queues, and runs the loop in a background task.

Hooks

AgentLoopConfig exposes hooks around each request and tool call: convert_to_llm, transform_context, prepare_request, prepare_next_turn, finish_turn, before_tool_call, after_tool_call, get_steering_messages and get_follow_up_messages. Tool-level hooks are declared on Tool (prepare_arguments) and AgentLoopConfig (before_tool_call, after_tool_call).

Events

AbstractAgentEvent covers agent start/end, turn start/end, message start/update/end and tool execution start/update/end. Use event_type for the wire name and event_to_json for a JSON-ready dictionary.

PiAgentCore.Agent — Type
Agent(; model=PiAISDK.Model("unconfigured"), tools=Tool[], messages=PiAISDK.AbstractMessage[],
      system_prompt=nothing, sections=nothing, thinking_level="off",
      tool_execution=:parallel, session_id=nothing, convert_to_llm=default_convert_to_llm,
      transform_context=nothing, get_api_key=nothing, finish_turn=nothing,
      prepare_request=nothing, prepare_next_turn=nothing, before_tool_call=nothing,
      after_tool_call=nothing)

Stateful agent that runs run_agent_loop in a background task, keeps its own message history, tool list and listener set, and exposes steering, follow-up and abort controls.

When the first message is not a PiAISDK.SystemMessage, a system message is created from system_prompt, sections and the tool declarations. Hook keywords are forwarded to AgentLoopConfig on each run.

Use prompt! to start a run, subscribe to observe events and wait_idle to block until it finishes.

PiAgentCore.AgentLoopConfig — Type
AgentLoopConfig(; kwargs...)

Configuration for run_loop and run_agent_loop. Every field has a default and the Base.@kwdef constructor accepts it as a keyword.

Hooks

  • stream_fn::Function: (model, context, options) -> stream; defaults to PiAISDK.stream.
  • convert_to_llm::Function: maps stored messages to LLM messages; defaults to default_convert_to_llm.
  • transform_context::Union{Nothing,Function}: optional LLMContext -> LLMContext transform applied per request.
  • get_api_key::Union{Nothing,Function}: optional model -> api_key.
  • prepare_request::Union{Nothing,Function}: optional (request, signal) hook returning context, model and/or thinking_level overrides.
  • prepare_next_turn::Union{Nothing,Function}: optional (turn, signal) hook returning extra messages.
  • finish_turn::Union{Nothing,Function}: optional (turn, signal) hook returning :end or :continue.
  • get_steering_messages::Union{Nothing,Function}: optional () -> messages drained between turns.
  • get_follow_up_messages::Union{Nothing,Function}: optional () -> messages drained after a turn without tool calls.
  • before_tool_call::Union{Nothing,Function}: optional (call, signal) hook returning (block=..., reason=...).
  • after_tool_call::Union{Nothing,Function}: optional (call, signal) hook returning result overrides.

Model and request options

  • model::PiAISDK.Model: model used for streaming; defaults to Model("unconfigured").
  • reasoning, session_id, identity, temperature, max_tokens, headers, cache_retention: forwarded to PiAISDK.StreamOptions.
  • tool_choice, sampling_params, metadata: carried for callers; not read by run_loop.
  • tool_execution::Symbol: :parallel (default) or :sequential; other values raise ArgumentError.

PiAgentCore.Tool — Type
Tool(name, description, parameters, execute; label="", prepare_arguments=nothing,
     execution_mode=:parallel)

Describe a callable tool exposed to the model.

parameters is a JSON Schema object validated by PiAISDK.validate_arguments before execution. execute is called as execute(tool_call_id, args, signal, on_update), where on_update receives partial results. prepare_arguments, when set, may rewrite args before validation. execution_mode is :parallel or :sequential; one sequential tool forces the whole batch of tool calls to run sequentially.

Fields

  • name::String: tool name sent to the model.
  • description::String: natural-language description.
  • parameters::Dict{String,Any}: JSON Schema for the arguments.
  • label::String: display label for user interfaces.
  • prepare_arguments::Union{Nothing,Function}: optional argument preprocessor.
  • execute::Function: tool implementation.
  • execution_mode::Symbol: :parallel (default) or :sequential.

PiAgentCore.run_loop — Function
run_loop(context, new_messages, config, signal, emit, stream_fn=config.stream_fn)

Run the agent loop over context.

new_messages are appended to the conversation and emitted before the first turn. Each turn streams one assistant message, executes its tool calls when present, and emits turn, message and tool events through emit. The loop stops when the assistant produces no tool calls, a tool result requests termination, the assistant reports "error"/"aborted", or config.finish_turn returns :end. Steering and follow-up messages from config are drained between turns.

Returns the messages produced by the run.

Arguments

  • context::AgentContext: conversation state; mutated in place.
  • new_messages: messages to append before the loop starts.
  • config::AgentLoopConfig: model, hooks and tool execution mode.
  • signal: abort token checked by providers and tools (may be nothing).
  • emit: callback invoked with every AbstractAgentEvent.
  • stream_fn: streaming function; assigned to config.stream_fn.

PiAgentCore.subscribe — Method
subscribe(agent::Agent, f::Function) -> Function

Register f to receive every AbstractAgentEvent emitted by agent.

Listeners run while the agent lock is held; a listener returning a Task is awaited, and listener errors are logged and stored in agent.state.error_message.

Returns a zero-argument function that removes the listener.
